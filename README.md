# Agentic Fraud Investigation Copilot

An LLM-agent system that takes a flagged transaction, autonomously gathers
context (transaction history, device/IP data, past cases), cross-checks it
against fraud rules and an ML risk model, and drafts a structured
investigation report — with a human analyst approving the final call.

## Architecture

```
Flagged Transaction
        │
        ▼
 gather_context     -> pulls transaction, device, customer history
        │
        ▼
 run_rule_checks    -> deterministic fraud rule engine (explainable)
        │
        ▼
 retrieve_history   -> RAG over similar past cases (precedent-based reasoning)
        │
        ▼
 score_risk         -> calls the trained ML risk-scoring model
        │
        ▼
 write_report       -> LLM drafts structured InvestigationReport (Pydantic)
        │
        ▼
 Human Reviewer     -> approve / reject in the Streamlit UI
```

Orchestrated with **LangGraph** as an explicit state machine — every node
reads/writes a shared state object, so each step is independently testable
and swappable.

## Project structure

```
fraud_copilot/
├── app.py                        # Streamlit UI
├── requirements.txt
├── .env.example                  # copy to .env and add your API key
├── data/
│   ├── transactions.csv
│   ├── device_ip_logs.csv
│   ├── past_cases.csv
│   └── labeled_dataset.csv
├── models/
│   └── risk_model.pkl            # generated by train_risk_model.py
├── generate_synthetic_data.py    # regenerate/tweak the synthetic dataset
└── src/
    ├── report_schema.py          # Pydantic schema for the final report
    ├── train_risk_model.py       # trains + saves the fraud risk model
    ├── agents/
    │   └── graph.py              # LangGraph orchestration (the core system)
    └── tools/
        ├── context_tools.py      # pulls transaction/device/history data
        ├── rule_engine.py        # deterministic fraud rule checks
        ├── retrieval.py          # RAG over past case notes (TF-IDF by default)
        └── risk_model_tool.py    # wraps the trained ML model as a tool
```

## Setup

```bash
# 1. Create and activate a virtual environment
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Add your API key
cp .env.example .env
# then edit .env and paste your GROQ_API_KEY
# (free key: https://console.groq.com/keys)
```

The synthetic data (`data/*.csv`) is already generated and committed, so you
can skip straight to training the model and running the app. If you want to
regenerate it (e.g. with a different fraud rate or more customers):

```bash
python generate_synthetic_data.py
```

## Run it

```bash
# 1. Train the risk-scoring model (only needs to be done once,
#    or whenever you regenerate the data)
python src/train_risk_model.py

# 2. (Optional) sanity-check the agent pipeline from the command line
python -m src.agents.graph TXN100002

# 3. Launch the full UI
streamlit run app.py
```

Open the local URL Streamlit prints (usually `http://localhost:8501`),
pick a transaction, click **Run Investigation**, and review the generated
report. Use the **Approve** / **Reject** buttons to log a human decision —
this is written to `data/analyst_decisions.csv`.

## Swapping the LLM provider

The graph uses `ChatGroq` by default (fast + free tier). To use OpenAI or
Anthropic instead, edit `src/agents/graph.py`:

```python
# Replace this:
from langchain_groq import ChatGroq
llm = ChatGroq(model="llama-3.1-70b-versatile", temperature=0, api_key=...)

# With, e.g.:
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0, api_key=...)
```

## Upgrading retrieval from TF-IDF to real embeddings

`src/tools/retrieval.py` uses TF-IDF by default so the whole project runs
offline with zero API calls beyond the final report-writing step. A
commented-out `EmbeddingRetriever` class in that file shows how to swap in
Chroma + `sentence-transformers` (or OpenAI embeddings) once you're ready —
the public `retrieve()` interface stays identical, so nothing else in the
agent graph needs to change.

## Notes on the synthetic data

The dataset is generated by `generate_synthetic_data.py` with deliberately
clean, separable fraud patterns (amount spikes, geo-mismatches, odd-hour
activity, new devices, high-risk merchants). This makes the ML model's
evaluation metrics look unrealistically perfect (precision/recall near
1.0) — that's an artifact of synthetic data, not a claim about real-world
performance. When discussing this project (e.g. in interviews), be upfront
that the value of the project is the **agent architecture and reasoning
pipeline**, not the model's raw accuracy on synthetic data. If you want more
realistic evaluation numbers, add label noise or overlapping distributions
between fraud/legit classes in `generate_synthetic_data.py`.

## Ideas for extending this project

- Add a **cost/latency logger** around the `write_report` node to report
  $ per investigation and report-generation time — great interview talking
  points.
- Add a **confidence threshold router**: only call the LLM for
  medium-risk-score transactions, auto-approve very low scores, and
  auto-escalate very high scores — shows cost-aware system design.
- Containerize with Docker and deploy the Streamlit app to Streamlit
  Community Cloud or Hugging Face Spaces for a shareable live demo link.
- Swap the TF-IDF retriever for the embedding-based one and compare
  retrieval quality.
